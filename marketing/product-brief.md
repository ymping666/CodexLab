# CodexLab 产品简报 · Alpha

## 一句话

**已经有 Codex 套餐，就用原生多智能体搭科研 Lab，无需另配 LLM API Key。**

英文定位：**A Multi-Agent Research Lab for Codex.**

第一层卖点：**Your Codex plan. Native subagents. No extra LLM API key.**

第二层价值：**五个科研角色，把文献、方法、实验与审查接起来。**

科研主张：**Artifacts first. Human decisions.** / **先有证据，再有结论。**

仓库：[ymping666/CodexLab](https://github.com/ymping666/CodexLab)。

## 产品对象与问题

第一批用户已经购买了支持 Codex 的套餐、登录了 Codex，也想用多智能体做 AI 科研。常见的 API 驱动框架往往要求另外配置模型 API Key、承担独立调用费用，并接入 SDK 或调度运行时。已有套餐与另搭 API 框架之间的接入门槛，是 CodexLab 要先解决的问题。

CodexLab 使用用户已登录的 Codex 和原生子智能体。框架本身不调用模型 API，也不实现自有编排运行时，所以无需额外 LLM API Key。实际执行正常消耗用户合适套餐中的 Codex 额度，不等于无限或免费运行。

在这条运行路径上，再提供科研 Lab 的组织方式：五个角色、共享材料和阶段检查。角色交接与证据追踪是第二层价值，应在介绍清楚原生执行和套餐使用方式之后展开。

| 用户上手问题 | CodexLab 的回答 |
|---|---|
| 为搭这个框架，还要开模型 API 吗？ | 不需要额外模型 API Key，使用已登录的 Codex |
| 再接哪套调度 SDK？ | 执行交给 Codex 原生子智能体 |
| 调用从哪里消耗？ | 既有合适套餐的 Codex 额度；计划资格和限制照常适用 |
| 科研如何分工？ | PI 加文献、方法、实验、Reviewer 四个子智能体 |

## 两层团队结构

本次产品开发由四个角色推进：leader 负责集成与开发流程，产品经理负责定位、Demo 和发布材料，两位工程师负责实现。这不是交付给用户的科研团队配置。

用户的科研团队是五个科学角色：根会话 PI / Lab Lead，以及 Literature、Method、Experiment、Reviewer 四个原生 Codex 子智能体。一个人同时保留科学决策和最终发布的责任。PI 应只委派当前有必要的工作，不为了凑人数并发启动所有角色。

## 首个使用闭环

1. 用户克隆仓库、确认已有可用的 Codex 登录和 Python 3.11+；无需另配 LLM API Key。
2. 用户输入研究主题，CLI 创建新工作区与角色配置；在工作区启动 Codex，审阅配置并完成原生信任提示，使用 PI 启动提示。
3. PI 确定问题边界和交付物；需要决策时交回用户。
4. 专门角色完成文献、方法、实验与审查材料，写入共享文件。
5. CLI 显示状态并检查阶段所需材料；人核实证据后决定继续或返工。

MVP 的可观察成功是上述闭环可以按文档复现，角色职责清晰且输出有可检查的落点。不能以“智能体返回了漂亮报告”代替科研质量验证。

## Alpha 范围与验收

| 能力 | 可验收行为 | 对外表述 |
|---|---|---|
| 新建工作区 | `init` 生成项目配置、角色指令和研究材料模板；已有目录拒绝覆盖 | 已实现后写“工作区脚手架” |
| 环境检查 | `doctor` 显示 Python 版本及 Codex 可执行文件和版本 | “前置检查”，不写“已验证真实会话” |
| PI 启动 | `prompt` 生成可直接用于 Codex 的启动提示 | “交给 Codex 原生子智能体执行” |
| 阶段状态 | `status` 列出工作区材料状态 | 文件状态，不冒充实时智能体运行状态 |
| 本地仪表盘 | `serve` 绑定 127.0.0.1，展示只读状态与 gate 结果 | 已实现的本地视图，外观与概念图分别说明 |
| 证据 gate | `gate` 检查各阶段结构与必要字段，返回可处理的缺失项 | 结构检查，不写“自动科学审查认证” |
| 合成 Demo | `demo` 写入明确合成的示例；不能通过科研 gate | “合成示例”，不写真实研究结果 |
| 概念视觉 | PNG 展示角色与证据流，标注 CONCEPT DEMO / SYNTHETIC EXAMPLE | 概念界面，不冒充完整在线产品 |

核心运行时是 Codex，Python CLI 不调用模型 API，不实现自有多智能体调度器。套餐资格、额度与工具能力仍由用户的 Codex 环境决定。

## 八周冲刺：目标示例

八周是一个可调整的科研管理框架，不是交付承诺。可采用的范围：先比较三个候选方向，再选择一个主要研究问题。

| 周期 | 目标材料 | 需要人的判断 |
|---|---|---|
| 第 1—2 周 | 候选问题、文献地图、创新碰撞检查 | 哪个问题值得投入 |
| 第 3—4 周 | 方法草案、失败判据、小规模试验 | 方法假设是否站得住 |
| 第 5—6 周 | baseline、主要实验、消融与运行记录 | 对照与预算是否充分 |
| 第 7—8 周 | 审查意见、补充实验清单、证据支持的初稿 | 可支撑哪些主张，是否继续或投稿 |

论文数、顶会录用数和指标提升不作为默认营销承诺。没有真实验证前不宣称案例、论文录用、benchmark 提升或用户规模。
